# 安全の仕組み

Akashi は「うっかり危ないコードを書けない」ことを、注意書きでなく**言語の決まりと検査**で守ります。
この文書は、その仕組みと、まだ守れないことを説明します。根拠の論文や調査は [設計の根拠](DESIGN.md) にまとめています。

## まとめ

| 守ること | 仕組み | 破ろうとすると |
| --- | --- | --- |
| 外に触る権利を広げない | 鍵（Console・Folder）を引数で渡したときだけ外に触れる | E300・E309・R509 |
| 決めたフォルダの外を読ませない | Folder の鍵は1つのフォルダの中だけ | R507 |
| HTML・SQL に外の文字を混ぜて形を変えさせない | 型紙＋値でしか作れない | E310・E311・R510 |
| 値が無い・失敗した場合を忘れない | null・例外が無い。Option・Result と漏れの無い match | E201・E210・E211 |
| 黙っておかしな値で進まない | 暗黙の変換無し・あふれたら止める・0 で割ったら止める | E201・R503・R504 |
| 約束が破れたまま進まない | requires・ensures を毎回確かめる。check で自動の入力も試す | R500・R501・R511・R512 |

---

## 1. 鍵（ケーパビリティ）

多くの言語では、どの関数でもファイルを読み書きし、通信できます。どこかの部品が乗っ取られたり、AI が思わぬコードを書いたりすると、その部品もプログラム全体と同じ権利を持ってしまいます。

Akashi では、外に触る関数は**鍵**を引数に取ります。

```akashi
fn report(console: Console, total: Int) -> Unit
do
  print(to: console, value: "total = " ++ to_str(value: total))
end

fn main(console: Console) -> Unit
do
  report(console: console, total: 10)
end
```

- 鍵を受け取れるのは `main` だけです。処理系が、動かすときに渡します。
- 鍵は**作れません**。`let` にしまう・返す・リストや型の欄に入れる・比べる、もできません（E309）。だから、鍵はいつも「引数を見ればわかる」場所にしかありません。
- 鍵を持たない関数は、外に触れません（E300）。**引数の型を見るだけで、その関数が外に何をしうるかがわかります。**
- ファイルを読む鍵（Folder）は、`--allow-read` を付けたときだけ渡されます。付けなければ R509 で止まります。

### Folder で読めるのは、渡したフォルダの中だけ

`read_text` は次の場合に R507 で止めます。

- `..` を含むパス、絶対パス、`\` や空文字を含むパス
- フォルダの中にあるが、リンクで外を指しているファイル（本当の場所を確かめる）

外を指していない「無いファイル」や「フォルダ」は、止めずに `Err` を返します。プログラムが扱うべき普通の失敗だからです。

## 2. HTML と SQL への注入を防ぐ

文字をつないで HTML や SQL を作ると、外から来た文字（`<script>` や `' OR '1'='1`）が、そのまま命令として読まれてしまいます。

Akashi の `Html`・`Sql` は、**書いたままの型紙**に**値**を差し込む関数でしか作れません。

```akashi
fn item(name: Str) -> Html
  ensures true
  example to_str(value: item(name: "<b>")) == "<li>&lt;b&gt;</li>"
do
  html(template: "<li>{}</li>", values: [html_text(value: name)])
end

fn main(console: Console) -> Unit
do
  print(to: console, value: item(name: "<script>alert(1)</script>"))
end
```

- 型紙が書いたままの文字でないと E310 です（`"<li>" ++ name` のような作り方を止める）。
- HTML の穴に入るのは `Html` だけです。`Str` は `html_text` を通すと `< > & " '` が置きかわります。もともと `Html` の値はそのまま入るので、二重に置きかわりません。
- SQL の値は文と別に持ちます（データベースに渡すときはプレースホルダとして渡す）。値が SQL として読まれることはありません。
- `Html`・`Sql` を `++` でつなぐことはできません。
- 文字からコードを動かす `eval` はありません。

## 3. null と例外を無くす

- **null が無い**：無いかもしれない値は `Option[T]` です。中身を取り出すには `match` で `Some` と `None` の両方を書きます。
- **例外が無い**：失敗するかもしれない操作は `Result[T]` を返します。`Ok` と `Err` の両方を書かないと通りません。
- 値を返す式を、受けずに捨てることもできません（E201）。だから、エラーを黙って無視する書き方ができません。

分散システムの重大な障害の 92% は、知らされていたエラーの扱い誤りから起きていました（[設計の根拠](DESIGN.md) の [2]）。Akashi はそれを書けない形にしています。

## 4. 黙っておかしな値で進まない

- 型は勝手に変わりません（`"1" + 1` は E201）。
- 整数があふれたら止まります（R504）。黙って小さな数に回りません。
- 0 で割ったら止まります（R503）。
- リストの範囲外は、`at` なら `None`、`get` なら止まります（R506）。
- 再帰が深すぎたら止まります（R505）。

## 5. 約束と自動の試し

- 関数の `requires`（呼ぶ側が守ること）と `ensures`（関数が守ること）は、動かしているあいだ毎回確かめます。
- `check` は、純粋な関数に自動で作った入力を何百も渡し、`ensures` が破れる入力を探して、一番小さい形で見せます。人が思いつかない端の場合（0・負の数・空の文字・空のリストなど）を拾います。

## まだ守れないこと

- **URL 属性**：`<a href="{}">` に外から来た URL を入れると、`javascript:` の URL が入りえます。外から来た値を `href`・`src` に入れないでください。
- **書き込み・通信の鍵**：まだありません（だから、ファイルを書いたり通信したりはできません）。
- **長い時間の処理**：再帰の深さとリストの大きさの上限だけで、時間の上限はありません。
- **部品（モジュール）**：まだ無いので、依存の乗っ取りへの備え（指紋での固定など）も、まだありません。入れるときの方針は [設計の根拠](DESIGN.md#入れなかった見送った後回し) にあります。
- **処理系そのもの**：処理系は Node.js の上で動きます。Node.js の脆弱性は Node.js の更新で直します。

## 使う道具の決まり（脆弱なものは使わない）

処理系そのものが脆弱だと、言語の安全の仕組みも意味がなくなります。だから、処理系を作り・動かす道具にも決まりを置き、CI で毎回確かめます。

| 決まり | 確かめ方（どれも無料） | 破るとどうなるか |
| --- | --- | --- |
| **依存はゼロ**。処理系・コンパイラ・テストは Node.js の標準の部品だけで作る。コンパイラも LLVM・Binaryen などを使わず、WebAssembly を0から書き出す | `test/deps.test.js` が package.json の依存の欄と、すべての `import` を見る | テストが落ち、PR がマージできない |
| **保守中の Node.js だけを使う**。`.nvmrc` は保守中の偶数版（今は 22）。CI は毎回その版の最新の修正版を入れる | 共通部品 node-test が、Node.js 公式の保守予定表（nodejs/Release）で保守中かを確かめる | 保守が終わった日から CI が落ちる（`.nvmrc` を上げる） |
| **既知の脆弱性がある依存は使わない**（もし依存を足すことになったら） | 共通部品 node-test が `npm audit --audit-level=low` を回す。Dependabot が古い・脆弱な版を知らせる | 低い深刻度でも CI が落ちる |
| **処理系のコードに脆弱性を残さない** | CodeQL（JavaScript とワークフロー）。`fail-on-alert: true` | 指摘が1件でもあれば CI が落ちる。毎週月曜にも調べ直す |
| **秘密の情報を入れない** | 共通部品 secret-scan（gitleaks） | CI が落ちる |
| **CI の部品も固定する** | 外の Actions は SHA で固定（共通部品 shared-workflows の決まり）。zizmor で検査 | 共通部品の Lint が落ちる |

依存をどうしても足したいとき：

1. 本当に標準の部品で書けないかを先に確かめる。
2. 保守されている（最近も更新がある）・既知の脆弱性が無い・それ自身の依存が少ないものを選ぶ。
3. `package-lock.json` を入れて版を固定する（`npm audit` と Dependabot が見張る）。
4. この表と `test/deps.test.js` を同じ PR で直し、理由を [設計の根拠](DESIGN.md) に1行書く。
